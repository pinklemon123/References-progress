# 程序运行与结果复现说明

## 1. 最快、最稳妥的运行方式

以下命令不要求安装 Python 3.12。Python 3.10、3.11、3.12 或 3.13 均可。

先在 PowerShell 查看电脑上已有的 Python：

```powershell
py -0p
```

较新的 Python Install Manager 也可以使用：

```powershell
py list
```

进入本目录后，用电脑默认的合格版本创建虚拟环境：

```powershell
cd G:\lunwen2\References-progress-submit\submission_package
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe reproduce_all.py
```

这里故意不执行 `Activate.ps1`。直接调用虚拟环境中的 `python.exe`，不会受到
PowerShell 执行策略影响。

如果列表显示已有 3.11，例如可明确指定：

```powershell
py -3.11 -m venv .venv
```

如果电脑没有 `py` 命令但有 `python` 命令，可改用：

```powershell
python --version
python -m venv .venv
```

也可以直接运行自动脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup_windows.ps1
```

## 2. 默认命令会做什么

`reproduce_all.py` 不重新进行限时随机搜索，而是：

1. 从原始附件重新读取巡检点和动态管制区；
2. 独立校验问题一正式路线；
3. 独立校验问题二正式路线；
4. 逐事件校验问题三算法 B 的 12 组结果；
5. 按赛题提供的五列示例模板生成 `result1.xlsx`、`result2.xlsx`、`result3.xlsx`；
6. 逐格回读三个工作簿，确认路线和 JSON 一致且没有额外结果列。

正式工作簿位于本目录根部，只包含：

- `UAV ID`；
- `1th Inspection Point`、`2th Inspection Point`……

基地编号 0 不属于巡检点，因此不写入正式表。距离、时间、目标函数、算法说明和问题三
逐事件记录保存在 `question1-3/results` 的 JSON/CSV 以及 `audit_materials` 中，用于复核，
不写入正式模板。

## 3. 为什么第一次激活失败

报错 `No suitable Python runtime found` 表示电脑没有 Python 3.12，因此
`py -3.12 -m venv .venv` 没有创建 `.venv`。后续再运行
`.\.venv\Scripts\Activate.ps1` 时，目标文件自然不存在。这个问题与执行策略无关。

## 4. 完整重新搜索（可选，耗时且不保证路线逐字相同）

先安装搜索依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-search.txt
```

问题一从头搜索示例：

```powershell
.\.venv\Scripts\python.exe .\question1\program\run.py --mode search --engine heuristic --quality fast
```

问题二、问题三的搜索参数和命令见各自 `program/README.md`。限时启发式包含随机起点、
CPU 调度和时间预算；重新搜索可能得到不同但同样可行的路线。论文结果的可复核性以保存
路线和独立校验器为准，不承诺每台电脑重新搜索后路线逐字相同。
